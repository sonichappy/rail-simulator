# 海外铁路票务系统：国际化与隐私能力补充

版本：v3 · 2026-09-16  
配套文件：`海外铁路票务系统业务模型_国际化与隐私增强版.drawio`

## 结论

v2 已具备票务核心分层，但只能说“有扩展位置”，尚不足以据此认定兼容多国个性化需求。本次 v3 增加第07–13页，并更新总览、个人信息引用及实施优先级；原始草图保留为第14页。所有新增节点和连线均可在 Draw.io 中编辑。

这次完成的是**设计补充**。目标运营商和国家尚未确定，具体支付方式、票价规则、票证格式和法律适用仍需逐市场验证，不能把配置项存在视为已接入或已合规。

## 1. 多市场兼容的基础：不要让一个国家字段承担所有差异

推荐分别记录租户、销售法人、销售市场、运营商、产品、渠道、品牌、语言、格式区域、币种及适用的数据处理政策。

例如同一订单可能由法国销售主体销售、包含不同运营商的运行段，旅客选择英文界面，美元仅用于展示，实际用欧元扣款。这些设置不应相互隐式覆盖。

配置解析器应对每个字段指定允许覆盖范围、优先级、合并方法和冲突处理。商业配置可覆盖默认值；适用法律限制、供应能力和防超售等约束必须独立验证。跨境规则不能简单地由“国家A配置优先于国家B”解决。

配置发布需带结构校验、场景回归、审批、生效时间、灰度和回滚记录。报价和订单绑定已使用的规则与配置版本，避免发布新配置后改变旧交易的含义。

## 2. 席位与票价的具体边界

服务等级使用运营商自己的稳定编码，面向用户保留原始名称与权益。跨运营商可以建立搜索分类，但不能强行认定两个同名等级权益完全相同。

住宿类型、等级、可选特征及计价单位分别建模。售卖整包厢时，应与包厢内单床位建立互斥占用关系。座位图保留真实布局、车厢与资源映射；语言切换不改变真实几何。

软偏好应允许不能满足并清楚反馈；硬条件不满足时，需要用户重新选择或同意替代方案。系统不应把“偏好申请成功”展示成“座位已保证”。OSDM 的乘车权利与订座区分可作为参考，但上述扩展是本项目的建议方案。[R1]

定价规则明确算法输入、执行顺序、冲突、舍入和失败行为。高级算法通过有版本的策略接口接入，不在运营后台放任意脚本。历史快照保存商业条件和版本；**个人信息不应因“不可变快照”而永久复制和保留**，应采用受控引用及单独的生命周期策略。

## 3. 支付与币种：配置能力之外还需要协议适配

支付方式与服务商分别建模。能力项至少涉及可用市场、商户、币种、金额范围、用户动作、授权、扣款、结果查询、撤销、退款与对账。

异步到账与临时票额保留期限必须协同。具体产品可以限制慢到账方式，也可以采用明确的延长占用或重新预订策略。支付结果未知时先查证，不能直接切换服务商再次扣款。

所有金额带币种，按明确精度表示。展示换算不得替代已确认的付款金额。支付服务商的接口金额精度可能与 ISO 标准不同，必须在适配器中转换；例如 Adyen 文档明确列出了这类差异。[P1] 具体方式是否可用，还须检查服务商能力及实际商户开通情况。[P2]

## 4. 语言与 UI：共享业务核心，允许体验变化

文案、品牌主题、页面模板和组件分别管理。普通界面文案可有回退语言；必须披露的合同或隐私文本需要经过审核，缺失时不能悄悄回退后继续发布相关产品。

采用语言标签管理文本语言，另行控制数字、日期等格式。[I1] RTL 语言须正确处理页面方向及双向混排，不能只把文字翻译后右对齐。[I2] 建议增加长文本、混排、键盘及读屏测试；座位图不能跟随页面盲目镜像。

页面字段、顺序和可用步骤可以配置，特殊选座或支付交互可以用受控组件扩展。所有业务、金额及权限条件仍由服务端校验。

## 5. GDPR 的设计含义与边界

### 适用范围与责任

GDPR 的适用取决于经营机构及处理活动等条件，不能按“欧洲国籍”或界面语言简单开关。[G1] 欧洲也不等于单一隐私法域，新增国家需要单独核对适用制度。

铁路运营方、票务销售方、支付方和云服务商的角色应按具体处理活动判定；不能把所有合作方默认归为处理者。适用的处理者协议、共享安排及职责应在接入前确定。[G3]

### 合法依据与敏感资料

购票、财务记录、客服及营销按目的分别确定合法依据，不把一次勾选同意当作所有处理的通行证。依赖同意的处理需支持撤回。残疾或健康证明可能涉及特殊类别个人数据，应同时核对 Art.6 依据和 Art.9 条件；设计上优先保留必要资格结果。[G2]

### 权利与保留

新增权利工单，连接资料、订单、客服、日志及外部接收方。通常须在一个月内回应；复杂请求等符合条件时可再延长两个月，但首月内需告知理由。不同权利存在适用条件，删除也存在例外，不能把注销账号实现为无条件删除全部财务记录。[G5]

本项目建议按数据类别与用途设置保留策略，覆盖缓存、分析副本和备份。合法保留数据限制用途；恢复备份后重施删除或限制记录。审计记录也应最小化，不能用审计为由永久保存完整个人信息。

### 部署与跨境

GDPR 并不要求一律将所有数据留在欧洲经济区，但跨境传输须满足相应条件。应登记存储、备份、接收方及境外访问路径，并核对充分性决定、标准合同条款等适用机制及必要评估；仅选择欧洲机房不足以解决这些问题。[G4]

### 事件及组织能力

新增知悉时间、风险判断、通知决策与证据记录。个人数据泄露的监管通报、对个人通知，以及处理者向控制者通知，是不同义务；图中分别体现时限与风险条件。[G6]

对可能造成高风险的处理，在实施前进行数据保护影响评估（DPIA）。[G7] 是否必须指定数据保护官（DPO）需按法定条件核对。[G8] 还需建立处理活动记录、培训、协议及演练，系统设计本身不能证明这些工作已经完成。

## 6. 每个市场上线前应通过的验收

- 新增一个运营商等级无需修改核心枚举；服务权益、翻译和检索映射准确。
- 覆盖无指定席、软偏好和硬选座；整间与单床互斥；换编组后能重排。
- 组合优惠、费用分摊、零位与三位小数币种及退款尾差正确。
- 支付回调重复、乱序、超时或晚到均不会重复收费；异步到账后有明确出票或退款结果。
- 同一业务在不同主题、语言及RTL界面上结果一致，长文本及关键合同无缺失。
- 模拟权利请求，能定位全部相关数据，并区分可删除与须保留部分。
- 模拟删除后恢复备份，及供应商数据处理失败，验证任务回执和人工恢复。
- 演练个人数据泄露响应；验证区域访问权限及跨境数据流登记。
